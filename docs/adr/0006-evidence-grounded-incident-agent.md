# ADR 0006: Evidence-Grounded Traffic Incident Agent using LangGraph

## Status

Accepted

## Context

TrafficLens-AI processes raw traffic video through a multi-stage pipeline:
1. **Computer Vision (CV) Pipeline**: YOLO11n vehicle detection, ByteTrack multi-object tracking, directional tripwire counting, tumbling window flow (VPM), polygonal ROI spatial occupancy and rule-based congestion levels, and stationary/stopped vehicle events with exact durations and timestamps.
2. **Multimodal Scene Understanding (VLM)**: Asynchronous SceneInterpretation pipeline extracting keyframes and querying Google Gemini for environmental context (weather, illumination, road surface, visibility hazards), roadway topology, and contextual event interpretations.

While both CV analytics and VLM scene interpretations produce structured artifacts, human operators, traffic engineers, and emergency services need synthesized, actionable **Traffic Incident Reports**. 

However, delegating incident report generation directly to a generative Large Language Model (LLM) introduces severe epistemic hazards:
- **Hallucinated Accidents & Violations**: LLMs frequently infer "car crashes", "reckless driving", or "illegal turns" from neutral stationary vehicle telemetry or high congestion.
- **Fabricated Metrics**: Generating plausible but fabricated vehicle counts, metric speeds (km/h) when the camera is uncalibrated, or precise timestamps not present in the CV data.
- **Tracker Identity Misinterpretation**: Confusing unique ByteTrack tracklet IDs (`track_id`) with persistent physical vehicle censuses.
- **Heuristic Over-Confidence**: Presenting heuristic congestion rules or speculative hypotheses as certified ground-truth measurements.
- **Visual Context Absence**: When VLM scene interpretation was not requested or failed, naive prompts may hallucinate weather or road conditions rather than acknowledging the lack of visual data.

To resolve these challenges, we require a dedicated agentic reasoning workflow that enforces strict **Epistemic Grounding**, transparent claim classification, and deterministically verified outputs.

## Decision

We adopt a **Bounded LangGraph Reasoning Workflow** for evidence-grounded incident report generation governed by the following architectural tenets:

### 1. Bounded Sequence Graph (No Unbounded Autonomous Loops)

We reject complex multi-agent architectures, dynamic tool-calling loops, web searches, and autonomous memory systems. The agent is structured as a deterministic, bounded sequence of five functional nodes in a LangGraph `StateGraph`:
1. `retrieve_evidence`: Reads CV analytics for the completed `ProcessingJob` and the latest `SceneInterpretation` (if available).
2. `normalize_evidence`: Harmonizes CV telemetry and VLM observations into a normalized `EvidenceContext`, explicitly flagging whether visual context is present.
3. `extract_traffic_events`: Pre-filters and structures significant traffic events (stopped vehicles, queue build-ups, flow rate drops).
4. `generate_report`: Invokes a configurable LLM provider with structured system prompts and enforces strict Pydantic v2 JSON output.
5. `validate_report_claims`: Runs a deterministic Python validation pass verifying every factual claim against the underlying telemetry, checking for forbidden hallucinated terminology ("collision", "crash", "infraction"), and demoting unsupported claims.

### 2. Strict Epistemic Grounding Invariants

Every incident report generated by the agent must strictly satisfy:
- **CV Facts**: Must cite real measurements from CV telemetry. Speeds in km/h are strictly forbidden unless camera calibration is supplied; only pixel displacement is permitted.
- **Tracker Identity Boundaries**: Tracklet counts must be described as tracked instances/tracklets, not physical unique vehicles.
- **Visual Observations**: Must cite completed VLM interpretation claims. When no VLM interpretation is available, visual observations are empty and an explicit limitation note is attached.
- **Event Causality**: Stoppages and congestion must be classified as observed conditions or supported inferences, never fabricated collisions or traffic violations.
- **Recommendations**: Must be explicitly partitioned into an operational suggestions section, clearly labeled as advisory rather than established factual events.

### 3. Dedicated Persistence with Full Audit History

Incident reports are persisted in a dedicated relational table `incident_reports` linked to `processing_jobs` via a foreign key with cascade deletion.
- Multiple report generations for the same job create separate immutable report records with distinct UUIDs (`rep_<uuid>`) and timestamps.
- Historical reports are never silently overwritten, providing a complete historical audit log for compliance and analysis.

### 4. Pluggable, Configurable LLM Provider Layer

The agent does not hardcode API keys or model names:
- Utilizes existing application settings (`GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_API_BASE_URL`).
- Supports a `MockIncidentReportProvider` for 100% deterministic, offline automated unit and integration tests with zero external API calls.

## Consequences

### Positive
- Guarantees factual reliability and zero hallucinated traffic incidents.
- Functions gracefully whether VLM scene interpretation is present or absent.
- Bounded execution ensures deterministic latency and zero risk of infinite LLM agent loops.
- Reuses existing project models, telemetry schemas, and grounding principles.
- Completely testable in CI/CD without live internet or paid API quotas.

### Negative
- Reports are constrained to observable telemetry and cannot hypothesize about off-camera events or unmeasured parameters.
- Extra latency for the LLM report generation step (~1-3 seconds).
